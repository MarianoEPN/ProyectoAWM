# Guía de contribución

## Flujo de trabajo

Nunca trabajar directamente sobre `main`.

Todo el desarrollo se realiza desde `develop`.

Cada nueva funcionalidad debe tener su propia rama.

Ejemplos

```
feature/login-web

feature/login-api

feature/dashboard
```

---

## Commits

Utilizar Conventional Commits.

Ejemplos

```
feat: create login page

fix: solve authentication bug

docs: update readme

refactor: simplify service

style: improve navbar

test: add login tests

chore: update dependencies
```

---

## Pull Requests

Todo cambio debe enviarse mediante Pull Request.

Debe ser revisado por al menos un integrante antes del merge.

---

## Código

Mantener nombres descriptivos.

Evitar archivos innecesarios.

Eliminar código muerto.

Mantener el proyecto compilando.
